# Reviews Analysis API

API-сервис для анализа пользовательских отзывов с использованием NLP-моделей.

Сервис:
- извлекает отзывы из MongoDB
- определяет тональность
- выделяет ключевые темы
- возвращает агрегированную статистику и детализированные данные

---

## Назначение проекта

Проект предназначен для:
- анализа тональности отзывов (positive / neutral / negative)
- выделения ключевых тем
- агрегации статистики для аналитики
- использования в админ-панелях, CRM и внутренних инструментах

## Как работает система

### Поток данных

1. Клиент вызывает `GET /reviews/analysis`
2. API получает отзывы из MongoDB (`isModeration = true`)
3. Для каждого отзыва:
   - анализируется тональность
   - определяется список тем
4. Результаты агрегируются
5. API возвращает:
   - статистику
   - список обработанных отзывов

---

## Обработка ошибок

Сервис спроектирован так, чтобы **ошибка одной модели не ломала весь анализ**.

### Поведение:

- ошибка sentiment → отзыв пропускается
- ошибка topics → отзыв пропускается
- ошибка модели логируется

Это обеспечивает:
- отказоустойчивость
- стабильный API

## MongoDB

Источник данных — коллекция отзывов в MongoDB.

### Используемые поля документа

- `feedback` — текст отзыва
- `name` — имя
- `city` — город
- `isModeration` — прошёл модерацию
- `createdAt` — дата

---

## NLP: Анализ тональности

Модуль: `services/sentiment.py`

Модель:
- `blanchefort/rubert-base-cased-sentiment`

Результат:
- `label`: positive | neutral | negative
- `score`: уверенность

---

## NLP: Анализ тем

Модуль: `services/topics.py`

Модель:
- `MoritzLaurer/mDeBERTa-v3-base-mnli-xnli`

Темы:

- качество питания
- работа гида
- маршрут тура
- логистика и трансфер
- проживание и отель

### Pipeline

1. detect_topics — получает все темы с вероятностями
2. rank_topics:
   - фильтрует по threshold (>= 0.3)
   - сортирует по score
   - ограничивает топ-N (по умолчанию 3)

## Производительность

В текущей реализации анализ выполняется на лету при каждом запросе:

``` python
for r in reviews:
    sentiment = analyze_text(feedback)
    topics = analyze_topics(feedback)
```

Это означает: - 2 ML-инференса на каждый отзыв - рост времени ответа -
нагрузку на CPU

---

## Рекомендуемая архитектура (production)

Анализ должен выполняться один раз при создании или модерации отзыва, а
не при каждом запросе.

Endpoint /reviews/analysis должен только читать готовые данные.
