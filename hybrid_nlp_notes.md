# Hybrid NLP Architecture Notes

## Hybrid-подход: ML + бизнес-правила

Модель тональности не всегда корректно определяет негативные отзывы в доменной области туризма.

Например:

- "Очень плохо организован трансфер"
- "Номер был грязный"
- "Трансфер задержали"

могут ошибочно классифицироваться как `neutral`.

Для повышения качества анализа поверх ML-модели реализован дополнительный слой доменных правил:

```python
NEGATIVE_MARKERS = [
    "не понравилось",
    "грязный",
    "плохо",
    "ужасно",
    "задержали",
    "опоздал",
]
```

Если текст содержит негативные маркеры, сервис может усилить итоговую тональность:

```text
neutral → negative
```

Такой подход является hybrid-архитектурой:

- ML-модель выполняет базовую классификацию
- бизнес-правила корректируют известные проблемные кейсы

Это позволяет:
- повысить точность на доменных данных
- компенсировать ошибки general-purpose NLP-моделей
- улучшить UX аналитики без fine-tuning модели

---

## Почему это важно

General-purpose NLP-модели не знают особенностей конкретной предметной области.

Для туристических отзывов негатив часто выражается через:

- задержки трансфера
- проблемы с проживанием
- организационные ошибки
- плохую логистику

Для человека это очевидный негатив, но модель может интерпретировать такие отзывы как `neutral`.

Hybrid-подход помогает:
- стабилизировать результаты
- уменьшить количество ложных neutral-классификаций
- повысить качество аналитики

## Edge Cases и анализ ошибок модели

Для оценки качества NLP-системы был создан отдельный набор edge cases — нестандартных и сложных примеров, на которых модель может ошибаться.

### Примеры edge cases

| Text | Problem Type |
|---|---|
| Ну просто великолепный трансфер, автобус опоздал на 6 часов | sarcasm |
| Норм | too short |
| Тур проходил в июне | factual / no sentiment |
| Гид супер, но отель ужасный | mixed sentiment |
| Тур имба, гид вообще топ | youth slang |
| Отель кринж, номер вообще жесть | youth slang |
| Маршрут вайбовый, но трансфер кринж | slang + mixed sentiment |

---

## Что показала evaluation

### 1. Модель плохо понимает позитивный молодежный сленг

Пример:

```text
Тур имба, гид вообще топ
→ NEGATIVE
```

Возможная причина:
- сленг отсутствовал в train dataset
- слова интерпретируются вне современного контекста

---

### 2. Негативный сленг распознаётся лучше

Пример:

```text
Отель кринж, номер вообще жесть
→ NEGATIVE
```

Возможная причина:
- негативный интернет-сленг чаще встречается в toxicity/sentiment datasets

---

### 3. Mixed sentiment приводит к усреднению

Пример:

```text
Маршрут вайбовый, но трансфер кринж
→ NEUTRAL
```

Модель одновременно видит:
- positive signal
- negative signal

и пытается усреднить итоговую классификацию.

---

### 4. Короткие тексты работают нестабильно

Пример:

```text
Норм
→ POSITIVE
```

Причина:
- слишком мало контекста
- ambiguous slang
- недостаточно signal для устойчивой классификации

## Evaluation loop

Для анализа качества системы используется следующий workflow:

```text
edge cases
→ inference
→ ошибки модели
→ анализ причин
→ business rules / preprocessing
→ повторная evaluation
```

Это позволяет:
- понимать реальные ограничения модели
- улучшать систему итеративно
- строить production-friendly NLP pipeline

## Slang-aware business rules

Для компенсации ошибок модели были добавлены domain/slang rules:

```python
POSITIVE_MARKERS = [
    "имба",
    "топ",
    "вайбовый",
    "пушка",
    "кайф",
]

NEGATIVE_MARKERS = [
    "кринж",
    "треш",
    "жесть",
    "такое себе",
]
```

Business rules позволяют корректировать prediction после inference.

Пример:

```text
raw model:
Тур имба, гид вообще топ
→ negative

after business rules:
→ positive
```

## Ограничения текущего решения

Текущая NLP-система использует general-purpose модели HuggingFace и не обучалась специально на туристических отзывах.

Возможные ограничения:

- ошибки классификации тональности
- слабая обработка сарказма
- неоднозначная интерпретация mixed sentiment
- чувствительность к формулировкам
- нестабильная работа со сленгом
- отсутствие domain-specific training

---

## Что можно улучшить дальше

Для production-качества рекомендуется:

- собрать собственный датасет отзывов
- выполнить fine-tuning модели
- добавить embeddings и semantic search
- перейти к RAG-подходу для аналитики
- внедрить vector search по отзывам
- анализировать тренды по темам и тональности
- добавить автоматическую evaluation pipeline

---

## Engineering вывод

ML-модель — это не "магия", а вероятностный инструмент.

В production-системах качество обычно достигается комбинацией:

- ML inference
- доменных правил
- preprocessing
- post-processing
- evaluation datasets
- анализа ошибок модели

Именно такой подход используется в реальных NLP/LLM системах.
