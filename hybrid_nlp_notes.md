# Hybrid NLP Architecture Notes

## Hybrid-подход: ML + бизнес-правила

Модель тональности не всегда корректно определяет негативные отзывы в доменной области туризма.

Например:

- "Очень плохо организован трансфер"
- "Номер был грязный"
- "Трансфер задержали"

могут ошибочно классифицироваться как `neutral`.

Для повышения качества анализа поверх ML-модели реализован дополнительный слой доменных правил:

```python
NEGATIVE_MARKERS = [
    "не понравилось",
    "грязный",
    "плохо",
    "ужасно",
    "задержали",
    "опоздал",
]
```

Если текст содержит негативные маркеры, сервис может усилить итоговую тональность:

```text
neutral → negative
```

Такой подход является hybrid-архитектурой:

- ML-модель выполняет базовую классификацию
- бизнес-правила корректируют известные проблемные кейсы

Это позволяет:
- повысить точность на доменных данных
- компенсировать ошибки general-purpose NLP-моделей
- улучшить UX аналитики без fine-tuning модели

---

## Почему это важно

General-purpose NLP-модели не знают особенностей конкретной предметной области.

Для туристических отзывов негатив часто выражается через:

- задержки трансфера
- проблемы с проживанием
- организационные ошибки
- плохую логистику

Для человека это очевидный негатив, но модель может интерпретировать такие отзывы как `neutral`.

Hybrid-подход помогает:
- стабилизировать результаты
- уменьшить количество ложных neutral-классификаций
- повысить качество аналитики

---

## Pipeline анализа

```text
text
→ HuggingFace pipeline
→ raw result
→ normalize label/score
→ business rules
→ final sentiment
```

---

## Ограничения текущего решения

Текущая NLP-система использует general-purpose модели HuggingFace и не обучалась специально на туристических отзывах.

Возможные ограничения:

- ошибки классификации тональности
- слабая обработка сарказма
- неоднозначная интерпретация смешанных отзывов
- чувствительность к формулировкам

---

## Что можно улучшить дальше

Для production-качества рекомендуется:

- собрать собственный датасет отзывов
- выполнить fine-tuning модели
- добавить embeddings и semantic search
- перейти к RAG-подходу для аналитики
- внедрить vector search по отзывам
- анализировать тренды по темам и тональности

---

## Engineering вывод

ML-модель — это не "магия", а вероятностный инструмент.

В production-системах качество обычно достигается комбинацией:

- ML inference
- доменных правил
- post-processing
- валидации результатов
- анализа ошибок модели

Именно такой подход используется в реальных NLP/LLM системах.
